# Blazegraph 2.1.6-rc.1

Дата: 21 ноября 2026 года. Первый предварительный выпуск форка
[`lebmax/blazegraph-db`](https://github.com/lebmax/blazegraph-db).
Тег: `v2.1.6-rc.1`. Среда сборки: Windows, Axiom JDK
`1.8.0_482-b10`, Maven `3.9.14`.

Выпуск объединяет все 26 коммитов `dev` от исходного `master` до `d52f54e`.
Сохранены embedded Java API, отдельный SPARQL-сервер, HA и scale-out.
Кластерные модули собираются профилем `cluster-integration`.

## Изменения

- Атомарная публикация snapshot и корректная обработка SPARQL OPTIONAL.
- Изоляция Sail-тестов, исправление литералов provenance и BCE-фикстур,
  устранение зависимости от десятичного разделителя.
- Освобождение файлов и корректные операции с ними на Windows: mapped input,
  durable queues, HALog и raw stores; проверка commit record в MemStore.
- Исправления timeout pipeline, split/join и перестроения full-text индекса.
- Совместимость SERVICE с живой DBpedia по HTTPS, локальная фикстура SERVICE
  и отдельный сетевой интеграционный тест.
- Обработка multicast в Windows, восстановление Jini/Apache River,
  ZooKeeper и серверных HA/scale-out модулей из публичной истории проекта.
- Исправление `ScaleOutClientFactory`, удаления HALog, локальной готовности
  после LiveResync, rejoin во время LOAD и освобождения буферов тестового HA.
- Управляемая LOAD для kill_B/kill_C; ошибки репликации относятся к UUID
  фактического адресата попытки, сохраняя исправного оставшегося follower.
- Согласованная версия POM и получение Git-ветки в обычном checkout,
  worktree и detached HEAD при формировании `BuildInfo`.

Изменения и доказательства по кластерным сценариям находятся в
[E0](../e0/2026-11-08-cluster-restoration.md) и
[разборе kill во время LOAD](../e0/2026-11-08-kill-during-load-synchronization.md).

## Сборка из тега

В PowerShell с установленным Axiom JDK 8u482:

```powershell
$env:JAVA_HOME = 'C:\Users\Axiom\.jdks\axiomjdk-1.8.0_482'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
git clone --branch v2.1.6-rc.1 https://github.com/lebmax/blazegraph-db.git
Set-Location blazegraph-db
mvn -B -ntp '-PDevelopment,cluster-integration' -DskipTests install
```

Команда собирает исходники и тестовые классы. `-DskipTests` означает,
что выполнение тестов требуется отдельным шагом.

Для воспроизведения кластерных проверок см.
[инструкцию стенда](../../integration/cluster/README.md).
Версия Java повышается поэтапно согласно
[плану развития](../plans/2026-11-07-blazegraph-development-plan.md).

## Известные ограничения

Статус prerelease обусловлен незавершённой валидацией кластерных режимов.
В полном кластерном прогоне на `163a813` выполнено 487 случаев, первично
неуспешны 53. Два HA-сценария прошли только при отдельном повторе; оставались
kill_B и 50 RDF scale-out случаев. Последующий `d52f54e` исправил kill_B/C
и прошёл 15 адресных HA и 9 core-проверок. Эти адресные проверки не заменяют
полного прогона на финальной релизной ревизии.

50 RDF scale-out падений и нестабильный
`TestHAJournalServerOverride.test_ABC_forceRemoveService_C` остаются открытыми
до свежего воспроизведения и исправления. Отключённые штатным upstream наборы
HA5/group-commit также требуют отдельного восстановления охвата.
Точный список и условия стабильного выпуска — в
[чек-листе 2.1.6](2.1.6-stable.md).

Свежие результаты сборки, адресных тестов и smoke-проверок артефактов
публикуются в `release-validation.json` вместе с файлами GitHub Release.
Исторические результаты не выдаются за новый полный прогон.
